# ADR 0003 — Use Catch2 as the test framework

## Context

The project needs a test framework so that every feature can be tested. The course requires Catch2.

Alternatives considered:

- **Google Test (gtest).** Widely used in industry, but requires more boilerplate and a separate `main()` function. Its macro names (`TEST_F`, `EXPECT_EQ`) are less readable for beginners.
- **Boost.Test.** Part of the large Boost library collection. Pulling in Boost for testing alone adds unnecessary weight.
- **No framework (plain assertions).** No setup needed, but no test discovery, no readable output, and no integration with CTest.

## Decision

Use Catch2 v3.7.1, downloaded automatically via CMake's `FetchContent`. Use the `Catch2WithMain` target so that Catch2 provides the `main()` function. Use `catch_discover_tests()` so that CTest can discover and run each `TEST_CASE` individually.

## Status

Accepted

## Consequences

- **Good:** Readable syntax (`TEST_CASE`, `REQUIRE`, `CHECK`) is easy to learn for a team new to C++.
- **Good:** `catch_discover_tests()` integrates with CTest, so `ctest` runs every test case and reports individual results.
- **Good:** No need to write a `main()` for tests — `Catch2WithMain` handles it.
- **Bad:** Catch2 is downloaded at configure time via `FetchContent`, adding to the first build time.
- **Bad:** Catch2 v3 requires C++14 or later (not an issue here since the project uses C++20, but limits backporting to very old compilers).
